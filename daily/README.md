## 两份报告同时维护

每个工作周期同时更新两份文档：

| 文档 | 入口 | 更新重点 |
|---|---|---|
| 长期工作报告 | [REPORT-PROGRESS.md](../REPORT-PROGRESS.md) | 累计目标、研究路线、已确认结论、反例、代表数据、当前状态与未解决问题；始终维护同一文件。 |
| 短期报告（日报） | 当期 `YYYY-MM-DD.md` | 本周期实际新增的工作、结果、失败、证据与下一步；按下文用户指定截止优先、默认17:00的规则归属。 |

每轮实验完成、中断、失败、出现影响判断的新证据，或到用户指定/默认截止收口时，先核验来源，再同时更新长期报告与当期日报。两份文档引用同一来源，数字、状态和下一步保持一致；在途结果写清证据截止时间，不把旧验收写成实时服务状态。长期报告中的结论发生变化时，保留原范围并说明新证据如何改变判断。

## 工作时间范围

1. **当日截止由用户明确指定；未显式说明则默认北京时间17:00。** 用户说“今日汇报范围已截止”“截至现在”时，按本次明确收口登记时刻记录。用户指定起点时同样优先。组会可能在16:30–17:00，但不会自动覆盖已明确的截止或默认17:00。
2. **下一份日报从上一份已确认截止时刻承接。** 不能因下一日默认17:00而把前一日下午已提前截止后的工作遗漏；没有明确上一周期记录时，起点暂按前一日17:00并注明待确认。
3. **截止后的当天工作，包括至24:00的下午和晚间，默认归入次日日报。** 次日凌晨、上午和截止前工作继续归入该份日报，午夜不另切换。
4. **已收口日报不继续追加之后发生的新工作。** 发现范围内遗漏或事实错误时，可作更正并注明原因；未来计划可保留为交接，但不能写成已完成。收口整理本身不增加实验量。
5. 跨截止的实验保留真实启动、阶段进展和完成时间；前周期记已发生增量，完整结果归入实际完成验收所在周期，不在两份日报重复统计。

## 记录方式

每份日报记录完成事项、主要结果、问题与限制、下一步及对应报告。实验数字来自阶段报告和完成记录，区分实测结果与机制推断；预热、诊断采样和正式窗口分别统计。尚未运行的计划不写成已完成结果。

补充进展时，先按实际工作时间和已确认截止确定所属周期，再更新对应日期文件，保留已经报告的失败与限制。阶段报告和日报分别维护：阶段报告保留完整方法与证据范围，日报记录周期内的新增进展。

## 后续维护约定

每轮实验完成、中断、失败，或完成一次历史结果复核后，按上述指定截止优先、默认17:00的规则更新所属工作周期的日报，并补齐本页索引。跨周期实验保留启动与阶段进展，在完成验收所在周期记录最终范围；历史复核归入本次复核所在周期，同时注明原测量日期，不增加“新跑实验”数量。阶段报告保存完整方法，日报保留周期内的新增进展和可访问的证据入口。

每个进展回答“做了什么、依据与预期是什么、结果如何”。按需要记录以下信息：

| 内容 | 记录要求 |
|---|---|
| 问题与依据 | 想解决的性能或正确性问题；机制解释标注为观察、推断或待验证假设。 |
| 预期与对照 | 改动变量、预期受益指标、需守住的退化门槛；尚未运行时写“待验证”。 |
| 固定条件 | 模型 revision、框架版本、卡数与并行布局、输入/输出长度、并发或到达率、缓存与预热方式、seed、是否启用 profiler。 |
| 实际结果 | 请求计划数/成功数/拒绝数/错误数、实际输出 token、计时长度、重复轮次及统计方式；保留失败与退化记录。 |
| 证据与状态 | 阶段报告、原始结果入口、汇总、完成/中断记录及校验清单。历史验收不写成实时服务检查。 |
| 下一步 | 解决当前不确定性的最小对照；未测的理论上限、硬件饱和程度和质量等价性保留为未验证。 |

当前性能记录见 [2026-10-31 日报](2026-10-31.md)，逐文件复核见 [单流汇总](../results/briefing-2026-10-31/single-stream-summary.json)。后续新增结果继续保留旧基准与独立回放的区别。

## 指标与图表口径

- 整体输出吞吐：实际输出 token 总数 / benchmark 完整计时秒数，注明四卡合计或每 GPU。
- TTFT、TPOT：注明单位、均值或分位数；`1000 / 平均 TPOT(ms)` 是换算值，不能标成逐请求速率算术均值。
- 复刻“单用户速度—系统吞吐”图时，分别记录两轴来源、是否包含输入处理、是否按 GPU 归一化，以及每个测点的 C、输入/输出长度、缓存和重复轮次。不能无条件用并发上限乘生成速度代替实测整体吞吐。
- profiling 的 kernel 活动、阶段累计时间和端到端延迟分别说明；未采集的硬件计数器或理论上限不补造百分比。

## 新建日报

使用以下结构，并在上表加入日期链接；条件简单时可合并段落，不为填模板虚构内容。

```markdown
# YYYY-MM-DD 工作日报

状态：进行中 / 已收口

工作统计范围（北京时间）：上一周期已确认截止至本周期截止；用户指定优先，未指定默认当日17:00。

截止来源：用户指定 / 默认17:00 / 暂定待确认

下一周期从本次截止承接：

工作主线：

## 今日进展

| 问题 / 实验 | 依据与预期 | 实际完成与结果 | 证据 / 状态 |
|---|---|---|---|

## 主要结果

记录负载、配置、实际请求数、轮次与指标口径；每个结论链接证据。

## 问题与限制

记录失败、退化、未完成及机制尚未确认的部分。

## 下一步

记录待验证问题和最小对照，不将计划写成结果。

## 相关记录

链接阶段报告、汇总与完成/中断记录。
```
